# Port Scan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a daily TCP-connect scan of LAN hosts (ports 1–1024 plus a home-relevant extra list) whose results show on each host page, as a count on the Hosts card, and in global search.

**Architecture:**
- A `portscan` module in sensr-agent: tokio connect scans with a semaphore and a rate limiter, scheduled by the agent, targets from the host inventory, results persisted to `ports.json`.
- An op and REST route for scan-now and read.
- The UI card on the host page, a count on the Hosts card, and search candidates.

**Spec:** docs/superpowers/specs/2026-11-24-port-scan-design.md

## Global Constraints

- **Ports:** TCP 1–1024 plus `554, 1883, 1900, 3000, 3389, 5000, 5001, 5353, 5555, 5900, 8000, 8008, 8009, 8080, 8123, 8443, 8554, 8883, 8888, 9000, 32400, 49152`, plus `hosts.portscan.extra_ports` (validated 1–65535, deduplicated).
- **Rate:**
  - at most **200** connect attempts/s in total;
  - at most **8** in flight per host;
  - **1.5 s** connect timeout;
  - one host at a time per interface; different interfaces may run in parallel.
- **Targets:**
  - hosts on internal interfaces with an IPv4 address, seen within **24 h**;
  - skip Quarantine hosts and the router's own addresses;
  - never WAN.
- **Schedule:** daily at `hosts.portscan.time`, default `"03:30"`, local time from the router timezone; `hosts.portscan.enabled` defaults to true.
- **Results:**
  - Per MAC: `{ last_scan: epoch, ports: [{port, service, first_seen, last_seen, closed_at?}] }`.
  - "new" means first_seen within 24 h.
  - Closed entries are kept 90 days.
  - Persisted atomically to the agent state dir as `ports.json`, loaded at start, with bounded size: at most 1024 ports per host.
- **API:**
  - `GET /api/v1/hosts/<mac>/ports` returns `{last_scan, scanning: bool, ports:[…]}`.
  - `POST /api/v1/hosts/<mac>/scan` returns 202 `{started:true}`, or 409 if a scan of that host is already running.
  - The hosts privilege covers both; the POST is refused for read-only users.
  - The hosts view gains `open_ports: Option<u32>`.
- **UI:**
  - Host page card **Open ports**: a table of Port, Service, First seen (with a `new` pill), the line "Last scanned …" or "Not scanned yet", and a **Scan now** button that polls until done.
  - Hosts card: "N open" muted, after the label line.
  - Global search: `port 23`, `23/tcp` and `tcp 23` match hosts with that port open; host hits link to the host page.
- **Project rules:**
  - no new crates; unsafe is forbidden;
  - no AI attribution;
  - bundle ≤ 430 KB brotli;
  - toolchain env as in earlier plans; `touch crates/sensr-ipc/src/*.rs` before builds, because the target dir is shared.

## Review Focus

1. **A host that drops every SYN.** Each attempt times out at 1.5 s, but with 8 in flight per host and 1046 ports that is about 3.3 min for that host. Other interfaces carry on, and the total stays bounded. Pin with `slow_host_bounded_time` using a fake connector with a virtual clock.
2. **Scan overlaps an agent shutdown or apply.** No panic; the partial result is not persisted as "all closed". Pin with `cancelled_scan_keeps_previous_results`.
3. **The host's IP changes between inventory and scan.** Results stay keyed by MAC, and a refused or unreachable IP doesn't wipe open ports unless the scan completed. Pin with `failed_scan_does_not_close_ports`.
4. **A malicious or huge `extra_ports` list** is capped and deduplicated, and validation rejects 0 and anything over 65535.
5. **Scan now spam.** A repeated POST while one is running gets 409, and at most 2 concurrent scan-now jobs run overall.

**Files:**
- Modify: `crates/sensr-schema/src/models/hosts.rs`. Add `portscan: PortScan { enabled (default true), time (HH:MM, default "03:30"), extra_ports: Vec<u16> }`, omitted when default, and validated.
- Create: `crates/sensr-agent/src/portscan.rs`, with these pieces:
  - a `Connector` trait for tests;
  - a `Scanner` with `scan_host(ip) -> Result<Vec<u16>, Cancelled>` and a rate limiter;
  - a `PortStore` (load, merge, persist with the `ports.json` atomic write);
  - the service-name table;
  - a daily schedule using the router's local time; reuse whatever the agent uses for timers and local time.
- Modify: the agent startup or slice applier to own the scanner, the same way the fingerprint sniffer is owned, and feed it targets from `HostCollector`.
- Tests: all five Review Focus items, plus `merge_marks_new_and_closed`, `schedule_next_run_local_time`, and `targets_skip_quarantine_router_wan_and_stale`.
