sensr

A firewall and router OS written in Rust, built on NixOS. It aims to match OPNsense feature for feature, with atomic upgrades and rollback.

In development: no images have been released yet. The buttons below go live with the first release. If you need a router today, use OPNsense for Raspberry Pi or VyOS for Raspberry Pi.

Related projects
  • opnsense-pi: OPNsense images for Raspberry Pi 4/5
  • vyos-pi: VyOS images for Raspberry Pi 4/5
  • OPNsense vs VyOS on the Pi 5: side-by-side speed and boot-time results

Benchmark: the performance evaluation measured OPNsense, VyOS and a NixOS + Rust prototype in x86 VMs. Over virtio with 8 TCP streams, Linux forwarded 25–26 Gbit/s and OPNsense 3.1. With 50 rules loaded, the prototype applied a one-rule change in 16 ms, OPNsense in 0.36 s and VyOS in 2.2 s. See also the startup comparison below: time until traffic flows on a real Pi 5 for all three, including this development build's on-device trial.

Timed from the reboot command, so shutdown, the Pi firmware and the boot loader come first (the "kernel starts" row): OPNsense boots through UEFI, VyOS straight from the Pi firmware. "Traffic flowing" is the LAN port up with an address; "fully ready" is OPNsense's last boot script or VyOS's config loaded. OPNsense from its own boot logs over 7 typical reboots (1 s resolution). The VyOS column is the router this site's author runs: pi5-1 (Pi 5, 16 GB, NVMe, three NICs, ntopng and AdGuard containers), measured 2026-11-18 over two reboots with an external ping/SSH watcher (≈1 s resolution) plus the router's own journal (short-monotonic) – LAN up 59.6 s, SSH 81.7 and 82.0 s, config loaded 85 s. That live configuration is what makes it slower than the 14 s/47–49 s figures measured on the same board with a minimal default config, which are in the Pi 5 comparison, boot time. VyOS has no web UI, so its figure is SSH.

The sensr column is the development trial on pi5-1 (16 GB, D0, three NICs) carrying an imported home-router config – Kea DHCP, Unbound, Suricata and 18 nftables chains – measured 2026-11-18. On the box: kernel 0.6 s, initrd 4.7 s, userspace 41.9 s, multi-user at 28.4 s, the LAN carrier 14.9 s and SSH listening 24.0 s after kernel start, and 43 s from the reboot command to SSH by wall clock. The kernel/traffic/ready rows above are that 43 s less the kernel-to-SSH interval, so they carry about a second of uncertainty; "fully ready" is the last unit (Suricata's signature update, 23.7 s) at 47.3 s after kernel start. The web UI's HTML is served, but its CSS, JS and wasm are not packaged in the build yet, so "UI ready" is SSH plus those pages.

The LAN figures measure the client's 1 GbE port, not the router: both directions ran at line rate, and the 2.5 GbE ports were not tested for lack of a second 2.5 GbE peer. Ceiling of the hardware, for reference; not yet measured with 5 GbE dongles.

Each blue USB 3.0 port5 Gbit/s signalling (USB 3.x Gen 1, 8b/10b coding), so at most 4 Gbit/s of data. A 5 GbE RTL8157 dongle can link at 5 Gbit/s, but on a PC's Gen 1 port it moved 3.47 Gbit/s in iperf3 (4.70 on Gen 2). Expect about 3.5 Gbit/s per port. Each port has its own USB controller in the RP1 chip.
RP1 ↔ SoCPCIe 2.0 x4, about 16 Gbit/s each way, shared by both USB ports and the onboard Ethernet. It is not the limit with two dongles.
Driversensr uses Linux, as vyos-pi does. Mainline r8152 drives the RTL8157 from Linux 7.1. sensr's Pi 5 image runs nixpkgs' mainline linux_latest (7.3 today), which has it, so no vendor kernel or backport is needed.

One-liner (Linux)

Writes the Pi 5 image straight to a disk. Replace /dev/sdX; everything on it is erased.

curl -fL https://github.com/itpick/sensr/releases/latest/download/sensr-pi5.img.zst | zstd -dc | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

Or, in Raspberry Pi Imager, choose Use custom and select the downloaded image.

First-boot settings

The FAT boot partition has a sensr/ folder, which works like the opnsense-pi/ folder in opnsense-pi. Put files there on any computer before the first boot. The last column says what the current development image already does with each one.

FileEffectToday
config.jsonA full sensr config (a backup export), applied once and then renamed to config.json.applied.Planned
seed.tomlA short hand-written seed: hostname, admin password hash or SSH keys, which NIC is LAN and WAN (by MAC), WAN type. Merged over the defaults, then renamed .applied.Planned
config.xmlAn OPNsense backup, converted to sensr config on first boot and applied.Yes: imported once onto a box with no config yet; the import report is kept on the box (/var/lib/sensr/import-report.txt). The interface names it uses must exist; until ifnames works, rename FreeBSD names such as igc0 to the Linux ones first.
ifnames<mac> <name> lines that pin NIC names, so USB adapters can't swap LAN and WAN.Planned
authorized_keysSSH keys for the admin account. SSH is key-only and never reachable from the WAN.Yes: keys for root
reboot-after-minutesA number N. A safety net for remote installs: sensr reboots N minutes after every boot until you delete the file; on a Pi 5 trial boot that brings back the system you had. Config changes made with sensr config commit --confirm roll back by themselves unless confirmed.Yes

sensr also writes to the folder: README.txt (this list) and, on the Pi, boot-log/ with one file per boot stage (early, running, shutdown, and the initrd's journal when it gives up), so a box that never reaches the network still leaves a post-mortem.

First boot

  1. Pi: update the EEPROM bootloader first (Raspberry Pi OS: sudo rpi-eeprom-update -a).
  2. Without a seed, the first NIC (eth0) is WAN (DHCP) and the second (eth1) is LAN with 192.168.1.1/24. Plug your computer into LAN.
  3. Planned: open https://192.168.1.1 and finish the setup wizard, which makes you set an admin password. Today the API answers plain HTTP on port 443 and the wizard does not exist yet.

Build it yourself

git clone https://github.com/itpick/sensr && cd sensr && nix build .#images.pi5
